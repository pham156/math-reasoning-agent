# Project Runtime

Save images, plots, and exportable figures in the home project under `figures/`. Keep large experiment data, models, checkpoints, JSONL outputs, environments, and plotting caches in scratch.

Run RL smoke dependencies in Apptainer through `scripts/rl/smoke_python.sh`. The Python image, isolated virtual environment, package/Hugging Face caches, temporary files, models, and outputs live under `SCRATCH_ROOT`; do not install dependencies into FuseMoE or the historical GRPO environment. `containers/rl-smoke.def` records the minimal Python container recipe. Code and small job-ID-first Slurm logs live in home. Source `scripts/setup_env.sh` for the canonical storage paths.

Use `scripts/rl/setup_smoke_runtime.sh` to prepare the scratch runtime. Check imports, objective tests, shell syntax, and `sbatch --test-only` before submitting the four-task smoke array. This is a setup test, not the 5,000-example benchmark study. Keep documentation paragraphs on single lines.

The next stage is `src.training.rl.pilot`: frozen 512-example Level 3-5 training slice, 300 disjoint stratified development examples, seed 42 for splits. `scripts/rl/submit_algorithm_pilots.sh` defaults to a Slurm dry run. Its `--submit` option queues four eight-update restart checks first and blocks the four seed-0 pilots behind successful checks. Continue only at four-update rollout boundaries; never silently resume a checkpoint with pending rollout slices. Each training segment stops at a safe boundary after 2.5 hours and has a four-hour Slurm limit. Pilots use 20 development examples for before/after diagnostics; these are not final benchmarks. Preserve FP32 trainable weights/BF16 compute from the passed smoke tests.

Pilot and restart-check runs require `full_determinism`, deterministic PyTorch operations, cuBLAS workspace configuration, disabled cuDNN benchmarking, and disabled TF32 before model initialization. The restart gate checks checkpoint-4 equality before continuation to distinguish initial numerical divergence from restore failures. Keep the 1e-7 weight threshold and exact rollout comparisons; do not bypass a failed gate.

For subsequent experiments, use checkpoint dependencies within each experiment, without artificial array task limits or barriers between independent models. The current historical pilot chain remains unchanged. Shared 300-example evaluation uses `src.evaluation.pilot_dev` and the same container runtime/grader as training. `src.training.rl.sft_pilot` is the matched-data, full-parameter SFT control; run its CPU `--prepare_only` audit before GPU submission. Keep SFT ground-truth solutions confined to the frozen training IDs. SFT evaluation depends on its training; combined summaries depend on their required evaluations.

Lean feasibility uses a separate scratch helper container and pinned Lean/Mathlib4.24.0 through `scripts/lean/lean.sh`. Large runtime/library/cache files stay scratch; preflight packs them into a read-only filesystem image to avoid loose-file metadata latency. Never start proof generation without successful positive/negative checker controls and statement compatibility preflight. Generate inside the Python GPU container, then invoke the host standard-library proof driver to launch the separate Lean container; nested Apptainer is unsupported. Reject unfinished proofs and unsupported proof constructs, audit allowed axioms, bound checking time/memory, and preserve raw outputs. This is inference-only feasibility, not a new RL training arm.
